# Security Policy

## Reporting a vulnerability

Please do **not** publish exploitable security vulnerabilities in a public issue.

When GitHub private vulnerability reporting or Security Advisories are available for the affected repository, use that private channel first.

Include:

- affected project and version,
- clear reproduction steps,
- expected security impact,
- relevant logs or proof of concept,
- suggested mitigation if you already have one.

Please avoid accessing data that does not belong to you, disrupting services, or performing destructive testing.

## Supported versions

Security fixes are generally focused on the latest maintained release unless a repository documents a different support policy.

## Public disclosure

Please allow reasonable time for investigation and remediation before public disclosure.

Security reports made in good faith are appreciated.
